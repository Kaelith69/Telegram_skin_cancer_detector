# 🔒 Privacy

This page explains exactly what data the bot collects, stores, processes, and transmits — and what it definitively does not do.

---

## The Short Version

- Your photos are **never stored** beyond the duration of a single analysis.
- Only the **text label** (e.g., `"Melanocytic nevi"`) is sent to the Gemini API. Not the image.
- No user data, Telegram IDs, or metadata is logged or retained.
- There is no database. No user profiles. No analytics.

---

## What Happens to Your Photo

Here is the exact lifecycle of every image sent to the bot:

### Step 1: Download to a temporary file

```python
fd, image_path = tempfile.mkstemp(suffix=".jpg")
os.close(fd)
await photo.download_to_drive(image_path)
```

- The image is written to a uniquely named file in the OS temp directory (typically `/tmp/` on Linux/macOS).
- The filename is generated by `tempfile.mkstemp()` — it is random and not guessable.
- The OS temp directory is local to the machine running the bot. It is not a cloud storage service.

### Step 2: Local inference only

```python
image = Image.open(image_path).convert("RGB")
inputs = processor(images=image, return_tensors="pt")
with torch.no_grad():
    outputs = model(**inputs)
```

- The ViT model runs **entirely on the bot's host machine**.
- No image data is transmitted to HuggingFace, PyTorch, or any external service during inference.
- The model weights were downloaded from HuggingFace Hub at setup time and are cached locally — inference does not make network calls.

### Step 3: Only the label goes to Gemini

```python
def fetch_condition_info(condition: str) -> tuple[str, str]:
    prompt = f"Is '{condition}' cancerous or non-cancerous? ..."
    data = {"contents": [{"parts": [{"text": prompt}]}]}
    response = requests.post(url, headers=headers, json=data, timeout=15)
```

- The only information sent to Google Gemini is the **text label** of the predicted condition (e.g., `"Melanoma"`).
- **No image is sent to Gemini.**
- **No Telegram user ID, username, or message ID is sent to Gemini.**
- Google's Gemini API is subject to [Google's Privacy Policy](https://policies.google.com/privacy).

### Step 4: Unconditional deletion

```python
finally:
    if os.path.exists(image_path):
        os.remove(image_path)
```

- The temp file is deleted in a `finally` block — meaning it is deleted **even if the model crashes**, even if Gemini fails, even if an unexpected exception is thrown.
- After `os.remove()`, the file no longer exists on disk.

## Data Retention Summary

| Data Type | Retained? | Duration | Where |
|-----------|-----------|----------|-------|
| Photo / image | ❌ No | Deleted immediately after analysis | OS temp dir (local) |
| Condition label (text) | ❌ No | Sent to Gemini during request, not stored locally | Google Gemini API |
| Telegram user ID | ❌ No | Never stored | — |
| Telegram username | ❌ No | Never stored | — |
| Message metadata | ❌ No | Never stored | — |
| Analysis results | ❌ No | Sent as Telegram reply, not stored locally | — |

## What the Bot Does NOT Do

- ❌ Does not save images to any database or file storage service
- ❌ Does not upload images to cloud storage (S3, GCS, Azure Blob, etc.)
- ❌ Does not send images to any external API (Gemini or otherwise)
- ❌ Does not log user identifiers or associate results with users
- ❌ Does not track usage, session history, or message frequency
- ❌ Does not require account registration or personal information
- ❌ Does not use cookies (it's a Telegram bot, there are no cookies)

## Third-Party Services

The bot relies on two external APIs. Their use is limited and described here:

### Telegram Bot API

- The bot communicates with Telegram's servers to receive messages and send replies via the `python-telegram-bot` library.
- Telegram's own privacy policy governs what Telegram stores on their servers.
- The bot does not retain any information from Telegram beyond what is needed to process the current message.

### Google Gemini 2.0 Flash API

- The bot sends a **text-only prompt** to Gemini containing the predicted condition name.
- Google's data handling for Gemini API requests is governed by the [Google Cloud Terms of Service](https://cloud.google.com/terms) and [Google's AI Privacy Practices](https://ai.google.dev/gemini-api/terms).
- As of the time of writing, Gemini API data is not used to train Google's models when accessed via API (not the consumer product). Verify this in Google's current documentation.

## Self-Hosted Deployments

If you deploy this bot yourself (on a VPS, Heroku, Railway, etc.):

- You control the environment. No third party beyond Telegram and Google has access to the data.
- Ensure your deployment platform does not enable persistent logging of stdout/stderr that could capture image paths or condition labels.
- Use environment variables for credentials — never hardcode them.
- Consider running behind a restrictive firewall that only allows outbound connections to Telegram's API and Google's API endpoints.

If you believe you've found a privacy vulnerability — for example, a code path where images are not being deleted correctly — please report it via the [Security](../SECURITY.md) disclosure process rather than opening a public issue.
